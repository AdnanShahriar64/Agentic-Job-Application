# Agent 0 — Job Intake: Link or Pasted Text → Resume JSON Files

## Purpose

Turn **one job posting** — given as a URL or as copy-pasted text — into every file the resume pipeline needs, then build the resume:

```
jobs/<Company_Role>/
  job_posting.txt          # exact posting text (source of truth for this job)
  job_requirements.json    # structured analysis (Agent 1, Task 2 rules)
  relevance.json           # keyword relevance judgments (Agent 2, Ranking)
  selection_scores.json    # generated by scripts/score_selection.py
  resume_selection.json    # selected IDs (Agent 2 rules)
  resume_content.json      # generated by script, never written by hand
output/<Company_Role>/Resume.pdf
```

This agent does **not** search for other jobs, write cover letters, modify master libraries, apply, or send anything.

Read these before starting, and follow their rules unless this file says otherwise:

- `agents/Agent1_job_discovery.md` — Sections 7–9 (requirement analysis, prioritization, gaps).
- `agents/Agent_2_resume_generator.md` — ranking, immutable achievements, page fitting, validation.

---

## Step 1 — Get the posting text

**If the user pasted text:** use it exactly as given. Do not fetch anything.

**If the user gave a URL:**

1. Fetch the page with the available web tool.
2. Keep only the posting itself: title, company, location, requisition number, responsibilities, qualifications, and any eligibility/clearance/citizenship statements. Drop navigation, cookie banners, "similar jobs" and footer text.
3. If the fetch fails, returns a login wall, or returns only a page shell (common for LinkedIn, Workday, iCIMS, Taleo, Indeed), **stop and ask the user to paste the job description text.** Do not reconstruct a posting from search snippets, memory, or a different listing of the same job.
4. If the URL redirects to a different job or says the posting is closed, report that and stop.

## Step 2 — Create the job folder and save the posting

Folder name: `jobs/<Company>_<Role>[_<ReqID>]`, using letters, digits and underscores only (e.g. `jobs/SwRI_Thermal_Engineer_18-01598`). If the folder already exists, tell the user and ask whether to overwrite or create a `_v2` folder.

Write `job_posting.txt` with this header, then the full posting text unchanged:

```
Source: <URL or "pasted by user">
Retrieved: <YYYY-MM-DD>
---
<full posting text>
```

## Step 3 — Write `job_requirements.json`

Analyze using Agent 1, Sections 7–9. Use exactly these keys (use `null` or `[]` when the posting does not state something — never guess):

```json
{
  "employer": "Southwest Research Institute",
  "job_title": "Engineer / Research Engineer - Thermal Engineer",
  "location": "San Antonio, TX",
  "employment_arrangement": "On-site",
  "requisition_number": "18-01598",
  "application_url": "https://...",
  "date_checked": "2026-10-28",
  "posting_file": "job_posting.txt",
  "eligibility_requirements": ["U.S. person status required"],
  "required_qualifications": [
    {"text": "BS in Mechanical Engineering with 5 years of thermal experience", "priority": "Critical"}
  ],
  "preferred_qualifications": [
    {"text": "Experience with LabVIEW", "priority": "Low"}
  ],
  "main_responsibilities": ["..."],
  "technical_skills": ["Heat transfer", "CFD"],
  "software_requirements": ["Fluent or STAR-CCM+"],
  "technical_keywords": ["thermal management", "liquid cooling"],
  "qualification_gaps": [
    {"requirement": "LabVIEW", "status": "Not established", "note": "No library evidence"},
    {"requirement": "Thermal modeling", "status": "Directly supported", "evidence_ids": ["EXP-002-C", "EXP-003-A"]}
  ],
  "match_score": 82,
  "match_score_note": "Heuristic only; not a hiring prediction."
}
```

Rules:

- `priority` is one of `Critical`, `High`, `Medium`, `Low` (Agent 1, Section 8).
- `status` in `qualification_gaps` is one of `Directly supported`, `Partially supported`, `Not established`. `evidence_ids` must be real accomplishment IDs from `libraries/EXP-00*.md`.
- Put every citizenship, U.S.-person, clearance, licensure (PE/EIT) or work-authorization statement in `eligibility_requirements`. These are never treated as optional.
- Do not paste the full description into the JSON; it lives in `job_posting.txt`.

## Step 4 — Write `resume_selection.json`

Follow Agent 2 exactly (ranking, mandatory Rheem/L&T/UTSA representation, EXP-005 limit, demonstration limit of 5). Format:

```json
{
  "target_company": "Southwest Research Institute",
  "target_role": "Thermal Engineer",
  "job_requirements_file": "job_requirements.json",
  "summary": "Concise factual summary relevant to the job.",
  "skills": [{"category": "Thermal and Fluids", "items": ["Heat transfer", "CFD"]}],
  "experience": {
    "rheem": ["EXP-001-E", "EXP-001-F"],
    "ltts": ["EXP-002-C"],
    "utsa": ["EXP-003-A"],
    "other": []
  },
  "demonstration_ids": [5, 6, 8],
  "selection_rationale": [
    {"id": "EXP-002-C", "R": 4.8, "E": 4.5, "focus_bonus": 0.5, "S": 5.24, "addresses": ["Thermal modeling", "C/C++"]}
  ]
}
```

- IDs are listed in the order they should appear.
- `summary` and `skills` may only state what the libraries support. A skill appears only if `libraries/Software_and_programming_skills_library.md`, `libraries/Technical_knowledge_library.md`, or a selected achievement supports it.
- Before choosing IDs, write `relevance.json` and run `python scripts/score_selection.py jobs/<Company_Role>` (Agent 2, Ranking). Copy R, E and S into `selection_rationale` from the resulting `selection_scores.json`; the build scripts ignore this field.

## Step 5 — Check, resolve and build

Run from the project root, in order. Fix and re-run on any error.

```powershell
python scripts/check_job_files.py jobs/<Company_Role>
python scripts/select_resume_content.py --selection jobs/<Company_Role>/resume_selection.json --output jobs/<Company_Role>/resume_content.json
python scripts/build_resume.py --input jobs/<Company_Role>/resume_content.json --output output/<Company_Role>
```

Then apply Agent 2's page-fitting loop (change only the ID lists, skills or demonstration IDs; max five revisions). Never edit `resume_content.json`, `resume_content.tex`, the template, or the libraries by hand to make it fit.

## Step 6 — Report to the user

Keep it short:

- Folder path and resume PDF path, page count and page-2 fill from `validation_report.json`.
- Match score and the top 3 reasons.
- **Eligibility requirements** (citizenship, clearance, licenses) — always listed first if present, with a note that the candidate must confirm them.
- Gaps marked `Not established`.
- Anything ambiguous in the posting, or any fact you could not verify.
